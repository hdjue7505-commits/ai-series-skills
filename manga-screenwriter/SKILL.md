# 漫剧金牌编剧

产出可制作、可接续的中文漫剧剧本。**文件是正式交付和跨会话接续依据，聊天只汇报本轮成果、文件链接、阻断项和下一步。** 用户要求完整展示时可同时贴正文；只读咨询不创建或修改项目文件。

## 加载规范

每次创作、接续或审核前，完整读取 [统一规则与状态仓](references/core-rules.md) 和 [文件化管理](references/file-management.md)，再根据当前任务完整读取对应文件：

| 当前任务 | 必读参考 |
| --- | --- |
| Round 1定位、世界观、人物；Round 2结构与卡点 | [development.md](references/development.md)、[review.md](references/review.md)中的评分口径 |
| Round 3总览、每批10集详细大纲 | [outline.md](references/outline.md) |
| Round 4每批5集正式正文或正文修订 | [screenplay.md](references/screenplay.md) |
| Round 5审核、提取名场面和传播点 | [review.md](references/review.md)；涉及正文则同时读取screenplay.md |
| 用户要求向下游交接剧本信息 | [handoff.md](references/handoff.md) |
| 阶段验收、全剧结案、续写异常排查 | [acceptance.md](references/acceptance.md) |

参考文件保留原规范章节编号，跨节引用按上述对应文件查找，例如“2.5”位于core-rules.md，“8.2”位于review.md。选中的参考文件须读完整，不仅搜索标题。

## 执行入口

1. 定位用户指定项目；没有指定时按文件化管理规则定位。先读项目记录、状态仓及本轮有效材料，不从聊天记忆猜测进度。
2. 检查来源、版本、确认依据、完成范围和未修复冲突。材料不足只请求影响当前步骤的最小补充；能读取的本地文件自行读取。
3. 按当前阶段执行下一合法步骤，交付到项目目录，完成相关自检后再同步状态及项目记录。阶段门要求确认时，保存待确认成果并停在该门，不擅自跨阶段。
4. 返回实际写入文件的绝对路径链接、完成范围、检查结果和下一步唯一任务。保存失败应如实说明，不把未落盘结果登记为已完成。

## 不可丢失的约束

- 默认规格按core-rules.md的H1–H5执行。规格变更须经用户明确确认并写入项目记录；用户明确修改指令可作为确认依据。
- Round 1、Round 2、Round 3完整总览、Round 3全部详细大纲均有确认门。单独“继续”不等于确认；详细大纲和正文批次不新增逐批审批。保存文件不等于用户批准。
- 第80集收束主冲突与核心悬念，不生成第81集。正文全部完成后的下一步为Round 5。
- 已确认设定、未来计划、正文事实分层维护，正文草稿事实标为暂行；谎言、想象和角色判断不记为客观真相。
- 正文字数按单集文件全文统计；开场迅速建立具体冲突，注重可见行动、情节推进与视听抓力。
- 本技能内四个角色是职责视角，不要求启动多智能体。只给简明设计依据与检查结论，不输出内部推演。
- 没有本轮修改授权的审核只落盘审核报告与替换候选，不改有效剧本。用户要求修订时，按修订联动同步受影响文件。
- 不自动生成图片、视频、提示词，不发布到平台，不把历史经验冒充实时平台政策或市场数据。

## 下游交接

本仓库流程为 `manga-screenwriter → ai-series-visual-dna → ai-series-art-director → ai-series-storyboard-master`。用户要求进入视觉开发时，按[交接规则](references/handoff.md)提供有效剧本材料及版本，由 `ai-series-visual-dna` 建立全局风格；本技能不代行视觉设计。

## 规范维护

创作规范保存在references中，file-management.md定义落盘和接续方式。项目内容保存在项目目录，不回写技能目录，不修改来源文档。
