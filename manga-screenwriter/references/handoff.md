## 9. 剧本下游交接

### 9.0 交接视觉DNA
用户要求进入视觉开发时，先确认采用真人电影质感，再交给 `ai-series-visual-dna`。动画项目不进入该真人流程。提供项目记录、已确认定位与人物世界设定、全剧结构、分集大纲、现有正文和审核结论的文件路径、精确版本、覆盖范围及待决项；沿用同一项目根目录。材料不完整时明确标为草案输入，不宣称全剧已完成或已通过审核。视觉DNA阶段负责生成与确认 `STYLE-BASE`，剧本确认不代替风格确认。

### 9.1 接口边界
本工作流以剧本为核心，保留供Seedance 2.0等下游分镜流程使用的可抽取信息；不直接生成视频提示词、参考图、资产包或生产调度。字段缺失时标“待补”，不能用抽取名义添加新剧情。
接口不要求在正文逐场重复一套十字段表。优先从正文与批次附录读取，只有用户要求交接时，才整理对应场景的抽取表。
| 字段 | 抽取内容 | 来源与约束 |
| --- | --- | --- |
| 来源定位 | 正文版本、集数、场号 | 所有记录必须能回指当前有效正文 |
| 画面主体 | 角色及动作对象 | 不自行添加出场人物 |
| 场景环境 | 地点、日夜、空间关系及剧情相关条件 | 未写天气、光影或材质时不臆造为既定事实 |
| 动作核心 | 谁对谁／什么做什么，发生何种后果 | 保留动作顺序、方向及因果 |
| 情绪核心 | 情绪及可见表现 | 不只输出抽象形容词 |
| 镜头建议 | 剧本明确指定或可选的视点建议 | 新建议标“建议”，不伪装成原文 |
| 关键道具 | 叙事作用与当前状态 | 关联正文事实，不提前使用未来道具 |
| 对白／旁白 | 原文、说话人、OS／VO性质 | 原文保真；删改须回到剧本修订流程 |
| 结尾画面 | 当前场或集最后的实际可见事件 | 终集提取收束画面，不强改为悬崖 |
| 情绪值／钩子功能 | 附录的相对设计值及悬念类型 | 无现成值时标待补；终集可填收束／余韵 |

### 9.2 转写原则
- 潜台词转为可见表情、动作、停顿或眼神关系；确有OS时保留声音属性，不强行全部视觉化。
- 世界规则只抽取已经在剧本中呈现的视觉证据和作用；尚无可见表现的设定标待补，不私自新增特效或解法。
- 悬念来自具体事件和信息差，不把“震撼”“吊胃口”当成画面内容。
- 单个视频片段的时长、参考能力、口型与声音支持，以实际使用的平台版本和已核实配置为准；不把15秒当作固定上限、固定片长或普适能力。
- 下游按动作可完成性和情绪节拍拆分片段，不把整集塞入单段，也不把“一个片段一个核心任务”误解为只能有一个动作。
- 名场面可以优先制作，但建立因果、空间和关系所必需的连接内容不能一概省略。
