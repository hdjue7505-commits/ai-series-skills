# AI Series Visual DNA

## 目标

以真人电影的摄影、表演与成像方式呈现题材自身成立的世界，不要求世界遵守现实物理。把全剧风格定义为跨人物、空间、明暗、节奏和高风险场面仍成立的可见不变量；候选、测试、评分、失败和修订默认内部完成，未通过门槛不输出正式产物。

```text
源材料与题材审计 → 内部候选 → 动态多组三联 → 评分与否决
→ STYLE-BASE 提炼与回注 → 发布
```

## 资源路由

只读取当前阶段所需资源，全部读到文件结尾；不要加载无关阶段契约。

- 任何正式产物：读取 [prompt-contracts.md](references/prompt-contracts.md)。
- 构建或修订 `STYLE-BASE`：再读取 [style-base-contract.md](references/style-base-contract.md) 中的自适应实拍定义与 [style-validation-protocol.md](references/style-validation-protocol.md) 中的质感测试和评分依据。

不要读取、复述或恢复归档旧版中的海报、命名、21:9 默认输出或导演 DNA 词库。

## 确认去重与交接

- 只对刚发布、尚未确认的精确 `STYLE-BASE` 版本请求一次确认；聊天中已经确认的精确版本不得再次索要确认。
- 用户在该产物交付后的直接回复中使用“确认”“通过”“批准”“继续”“按此执行”或同义表达，且没有并列版本或冲突指令时，视为确认当前唯一精确版本；不得要求用户重复产物 ID。
- 用户把确认与继续合并在同一条消息时，立即消费本次确认并交接给 `ai-series-art-director`；不得先回复“已确认”再等待第二次“继续”。本 Skill 仍不代行下游产物。
- 已确认版本收到“继续”时，不重发、不重确认；只报告精确交接版本并进入下游 Skill。只有发布了新版本才重新建立一次确认门禁。
- 存在多个待确认版本、用户同时提出修改或指向不明时，才用一个简短问题消除歧义。

## 固定边界

- 视觉本体固定为真人电影长剧：真人角色以真实演员感呈现，实景、实体布景、数字场景与电影级生物/灵体视效均可使用，不要求每幅画面都有人类演员。拒绝动画、动漫画、游戏宣传图、概念设计图和商业广告本体，不否决服务真人电影的 CGI/VFX 制作技术。
- 正式提示词正文使用英文，`STYLE-BASE` 与可选验证图固定 16:9。
- 默认不调用图像生成。仅在用户明确要求生图验证、样片验证或验证图时生成已通过提示词审核的测试组。
- 不输出角色、场景、视频、逐集、逐场或逐镜头提示词，不设计秒级时间轴，不做多模型适配，不输出片名、海报、封面或发行视觉。
- 不调用或代行下游美术建模、分镜与视频提示词阶段；只把已确认的精确 `STYLE-BASE` 版本交给 `ai-series-art-director`，并供后续 `ai-series-storyboard-master` 读取同一版本。
- 区分剧情事实、用户偏好、可撤销设计选择和关键未知。缺失普通视觉细节时依材料提出风格候选；会改变叙事身份、能力、关键因果、必须满足的空间关系或与已确认风格冲突时先询问。内部压力测试的新增事件不进入正史。
- 只把跨组稳定规则写入母提示词；角色身份、具体地点、剧情动作、情绪结果和单镜头参数不得升级为全剧不变量。

## 自适应实拍原则

- 电影感来自观看关系、世界内成立的光色与材料行为、真人表演及一致的成像响应，不来自滤镜、黑边或缺陷堆叠；可信度指世界内自洽和电影视效融合，不等于现实可建造或符合地球重力。
- 根据源材料与已确认偏好选择主成像基底；不默认35mm、复古、欠曝、低饱和、低清或做旧。明亮、洁净、暖色和高彩度同样可以成立。
- 题材表达强度依材料与偏好确定，不预设克制或宏大。仙气可来自造型、空间、材质、色彩、气流和超自然现象；不统一套白衣云雾蓝光，不为反游戏质感而削掉悬浮、神兽、灵体、异质材料或强法术。现实题材不主动添加超自然设定。
- 只提炼跨组成立的质感规则及其适用条件；光学缺陷不是必选项，具体机位、动作和局部光学事件仍属于测试变量。

## 阶段流程

### 0｜源材料审计

提取剧情事实、偏好、设计空间、关键未知、不可丢失的题材视觉特征及世界内超常规则，建立内部角色、场景与风险清单。完整材料标记 `complete`；片段、部分集数或未解析材料标记 `draft`。默认不公开审计过程。

### 1｜内部候选

视觉方向明确时建立一个候选；存在会改变最终画面的实质歧义时建立三个正交候选。为每个候选登记视觉命题、物理来源、证伪条件和最高风险。候选不要求用户预选。

### 2｜动态多组三联

按验证协议构建 `REL`、`WORLD`、`RANGE`、`STRESS` 四组三图；跨时代、多地域、战争、怪物、特殊环境或身份系统出现新增风险时追加三图组。每组三图必须改变画面任务与至少四个构图变量，不能成为同画面换角度。

### 3｜评分与否决

严格执行验证协议：每组必须 ≥82，跨组一致性必须 ≥88；任一一票否决立即失败。同一候选两轮定向修复仍不通过则淘汰。全部候选失败时只报告必须由用户解决的事实冲突或缺失决策。

### 4｜STYLE-BASE 提炼与回注

从放行测试中提取跨组不变量，删除实体、剧情、单镜头和偶然细节。母提示词必须 ≥90，再回注全部测试组；任一分组、总体或否决项退化时只修订母规则并复审。通过后按覆盖状态发布正式版或草案版，返回精确产物 ID 与文件路径，然后停止等待用户确认。

### 5｜可选图片复核

只生成已经通过审核的提示词。每张独立生成；失败时只修改有稳定因果证据关联的条款，不批量抽取幸运样本。用户明确要求单画布拼图时可以服从，但必须先说明该请求覆盖默认独立生成边界。

## 确定性验证

写入正式产物后运行统一校验器；语义放行仍由对应契约和验证协议负责。

```powershell
python scripts/validate_artifacts.py <STYLE-BASE.md>
python scripts/validate_artifacts.py <DNA-directory>
```

校验失败时只修对应条款并重跑。脚本只核对文件结构、语言与画幅并报告词数；不得用通过结果替代题材保真、真人本体、视效融合、跨组一致性或原创隔离审核。

## 交付

正式产物只写入项目根目录的 `DNA/`，使用版本化文件名并保留旧版。`STYLE-BASE-[实际发布版本]` 是后续角色建模、场景建模与视频风格转译的唯一全局风格来源。聊天只返回精确产物 ID、当前文件链接和简短状态，并明确等待用户确认；确认后下一阶段只能调用 `ai-series-art-director`，本 Skill 不继续执行。除非用户明确要求，不粘贴提示词正文、候选、测试组、评分或失败记录。
