# AI Series Art Director

## 目标

以真人电影的摄影、表演与成像方式设计题材自身成立的世界，不要求幻想造物遵守现实物理。把主要角色、连续性群众系统、重复地点与重要道具转化为可版本化、可追溯、可供逐场视频提示词引用的美术资产。审计、设计与建模连续完成，首次合格交付直接为 `approved`；用户明确提出修改时才创建新版本。

```text
剧本 + 已确认 STYLE-BASE
→ 资产审计与设计选择 → 锁定本次精确 ASSET-INDEX ID
→ 角色/群众/场景/道具建模 → 写入 approved 索引 → 校验
→ 交给分镜阶段
```

## 必读资源

- 任何正式产物：完整读取 [artifact-contracts.md](references/artifact-contracts.md)。
- 识别资产、构建提示词或执行语义审核：再完整读取 [continuity-quality-protocol.md](references/continuity-quality-protocol.md)。

## 输入门禁

开始前同时确认：

1. 用户提供剧本或可定位到具体场次的剧情材料。
2. 用户提供精确版本文件 `DNA/STYLE-BASE-[版本].md`，且明确确认该版本。
3. STYLE-BASE 已通过 `ai-series-visual-dna` 的结构校验与语义审核，明确声明真人电影 `live-action` 本体；允许 `cinematic VFX`，不接收纯动画、动漫画、定格动画或混合动画 STYLE-BASE。

缺少任一项时停止，只报告缺失项。禁止使用 `latest`、`current`、未版本化路径或从聊天记忆重建 STYLE-BASE。

收到动画风格时说明本技能已改为真人电影专用，不擅自把动画转真人、不迁移或删除旧资产。现有动画上游的旧交接指向不构成接收授权。

## 直接批准与版本迭代

- 新产物首次合格交付固定为 `approved`，不创建仅状态不同的 `awaiting-confirmation`、`confirmed-for-modeling` 或 `awaiting-asset-approval` 副本，也不索要批准确认。
- 开始建模前先锁定本次精确 `ASSET-INDEX-[版本]` ID；全部实体继承该 ID，随后写入同一 ID 的 `approved` 索引并统一校验。
- 用户明确提出实体、资产范围或参考图修改时，才按可见变化升级对应实体并写一个新的 `approved` 索引；不得为状态迁移单独递增版本。
- 缺少脸型、服装、纹样、建筑细部或能量外观时主动设计，在建模方案中标为 `design-choice`，不为普通设计逐项索要确认。“继续”不授权增改叙事身份、能力、关键因果或必须满足的空间关系；这些关键未知或与 STYLE-BASE 的冲突才集中询问。
- 旧项目中的三种中间状态仅作读取兼容，不用于新交付。

## 模式路由

- 没有 `approved` 资产索引：连续执行资产审计与建模生产，直接发布一个 `approved` 索引。
- 已有 `approved` 索引且用户明确要求修改：只修指定实体或资产范围，直接发布新的 `approved` 索引。
- 用户明确要求生成参考图：只对已通过提示词审核的指定资产执行“可选生图模式”，完成后直接发布新的 `approved` 索引。
- 用户要求分镜、片段或视频提示词：停止并交给下游 Skill，不在本 Skill 内代行。

## 1｜资产审计模式

审计全部已提供材料，区分事实、用户偏好、可撤销设计选择和关键未知。设计选择可形成稳定连续性锚点，但不得冒充原文事实或另造全局风格。

- 收录需要跨场次保持身份连续的主要角色：核心行动者、关键关系角色、反复出现者或虽出场少但承担剧情转折者。
- 把共享组织身份、制服、层级、职业动作或制度造型且需要跨场一致的非命名人群归并为一个群众演员系统；不为单个路人建资产，不把群众系统伪装成主要角色。
- 把每个稳定空间母体归并为一个核心场景；日夜、天气和临时陈设通常作为同一场景的变体，只有永久布局、时代层或物理结构改变时拆分新场景。
- 把跨场流转、承载身份或证据、触发关键因果、需要近景识别或存在可追踪状态变化的物件收录为重要道具；普通家具、消耗性杂物和永久绑定角色且无独立流转的微小配饰仍归入角色或场景。
- 同一重要道具只建立一个 `PROP` 资产；角色和场景只记录佩戴、存放或使用关系，不复制一套冲突的物理设定。
- 神兽、灵体等依叙事职责归入既有 `CHAR` 或 `CROWD`，固定环境现象归入 `SCN`，独立法器归入 `PROP`；不为题材新增资产类型，不强制把非人生命改成人类或普通动物。
- 材料不完整时把覆盖状态标为 `draft`，不得补写为剧本事实。

审计完成后先锁定一个尚未使用的精确 `ASSET-INDEX-[版本]` ID，并立即进入建模；不写待确认索引。材料不完整时保持 `coverage: draft`，但最终状态仍为 `approved`。

## 2｜建模生产模式

只处理本轮已锁定的精确索引范围，不静默新增实体。发布前发现漏项时回到本轮资产审计并补齐；已发布后发现漏项时仅在用户明确要求修改后创建新版本。

相关 STYLE-BASE 规则须转译为可执行的真人电影实体表达，而非只写“follow STYLE-BASE”；视效技术统一用 `cinematic VFX` 表述，不把 `3D VFX` 写成媒介标签。既有建模字段名不改，不适用时填明原因及对应形态。白底或中性背景只简化展示，不能删除固有透明、发光或悬浮；同时保持轮廓、结构和识别信息可核对。

### 角色

为每个主要角色建立十项建模方案，并生成：

- `Character Model-Sheet Prompt`：英文、可直接生图、16:9，显式继承真人电影本体及所需视效融合规则，使用纯白识别背景；左上面部或非人核心识别部位特写、左下关键细节、右侧正面/侧面/背面全身三视图。
- `Character Base`：英文精炼版，保留可见身份、造型、实体固有的超自然特征及连续性锚点；不包含背景、剧情动作、当前施法表演、镜头、画质或全局风格。

### 群众演员

为每个群众演员系统建立十项建模方案，并生成：

- `Crowd Model-Sheet Prompt`：英文、可直接生图、16:9，显式继承真人电影本体及所需视效融合规则，使用纯白识别背景；展示组织轮廓、层级或工种变体、正侧背结构、材质与配饰细节，以及世界设定允许的脸部、年龄、体态或非人个体差异，禁止机械复制。
- `Crowd Base`：英文精炼版，保留群体身份、构成、层级、服装系统、配色、携带物、群体固有的超自然特征、连续性锚点与允许变化；不写具体剧情动作、人数、队形、镜头或全局风格。

### 场景

为每个核心场景建立十二项建模方案，并生成：

- `Scene Model-Sheet Prompt`：英文、可直接生图、16:9，固定使用 `2x2 four-panel grid`，按左上全景图、右上俯视图、左下侧视图、右下特征图排列，具体视图职责见资产契约。四格必须表现同一场景与同一稳定空间母体，共同覆盖前中远景、入口出口、关键道具、有世界依据的光源/光值、调度区和站位区，不得拼接不同地点或条件变体。
- `Scene Base`：英文精炼版，保留空间、材料、布局、固定道具、光源及世界内稳定结构；悬浮、洞天出入方式等不能只留在图版提示词中。不包含具体角色、剧情动作、镜头或全局风格。

### 重要道具

为每个重要道具建立十二项建模方案，并生成：

- `Prop Model-Sheet Prompt`：英文、可直接生图、16:9，显式继承真人电影本体及所需视效融合规则，使用中性识别背景；展示三分之四主视图、正侧背顶视图、人体尺度参照、材料与结构细节、开合/炼制/能量运行逻辑，以及剧本成立的状态变体。
- `Prop Base`：英文精炼版，保留类别、尺寸、轮廓、结构、材料、固定标记、接触或非接触操控关系、固有超自然特征、初始状态、允许状态与连续性锚点；不写当前使用动作、剧情结果、镜头或全局风格。

角色、群众、场景与道具正式文件必须继承同一精确 STYLE-BASE 与本轮锁定的同一索引版本。不得复制、改写或另建冲突的全局综合色、成像介质、镜头家族和材质规则。

悬浮山门或超常建筑须有稳定相对布局、尺度、出入方式与可行动区域，不要求现实工程可建。法器允许自发光、非现实结构及悬浮操控，不强加机械解释。若原文要求的题材表现被 STYLE-BASE 禁止或无法承载，交回视觉 DNA 修订并等待新版本确认，不私自删减题材或改写母风格。

## 3｜审核与发布

按质量协议逐实体审核事实与设计来源、题材保真、真人电影与视效融合、连续性、版式和精炼版隔离。写入后运行：

```powershell
python scripts/validate_artifacts.py <index-or-ART-directory> --style-base <STYLE-BASE.md>
python scripts/validate_artifacts.py <character-or-scene-files> --style-base <STYLE-BASE.md> --index <approved-index.md>
```

任何失败只修对应实体，不批量重写已通过资产。全部资产通过后写入本轮已锁定的索引，列出当前实体文件与参考标签，状态直接为 `approved`，供 `ai-series-storyboard-master` 读取。不得为审批状态复制第二份内容相同的索引。

## 4｜可选生图

默认不生图。用户明确指定资产并要求生图时：

- 只使用已经通过审核的 Model-Sheet Prompt。
- 每个角色、群众系统、场景或道具独立生成一张，不把多个资产合在同一画布。
- 场景参考图虽包含四格，仍只表现一个场景资产；不得把不同地点、条件变体或多个空间母体拼成四宫格。
- 保存到 `ART/references/[参考标签去掉 @].png`。
- 视觉复核失败时只修改有稳定因果证据关联的实体条款。
- 后补参考图时升级实体次版本，使 `reference-image`、参考标签和图片文件使用同一新版本，再直接写入一个新的 `approved` 索引；不增加图片审批门禁，不原地修改实体或覆盖已登记参考图。

## 固定边界

- 只设计真人电影及电影级视效资产，不接收或改造动画、动漫画或混合动画风格；不因生物、灵体或数字场景由 CGI/VFX 制作而将其误判为动画本体。
- 禁止塑料人物、游戏 key art、概念图本体、广告摆拍、视效脱节或未授权 IP；不笼统禁止魔法、悬浮、粒子、异质材料或超常尺度，不靠削弱仙气与奇观取得所谓真实感。
- 正式英文提示词正文不得混入中文；中文只用于资产名、建模方案和交付状态。
- 不设计逐场表演、镜头、运镜、片段时长、对白或 Seedance 视频提示词。
- 不擅自新增或改变叙事身份、组织关系、能力、关键因果、必须满足的空间关系、道具归属或状态变化；未明确的视觉细节可在这些边界内主动设计，标记来源并固定连续性。

## 交付

正式产物只写入项目根目录 `ART/`，使用版本化文件名并保留旧版。聊天只返回本阶段精确 `approved` 产物 ID、文件链接与校验状态，不请求审批确认；只有 `approved` 索引才能交给 `ai-series-storyboard-master`，本 Skill 不代行分镜。除非用户明确要求，不粘贴英文提示词正文或内部审核过程。
