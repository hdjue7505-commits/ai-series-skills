# 从第一个念头开始

[返回首页](../README.md) · [制作指南](workflow.md) · [故事示例](../examples/last-train.md)

## 安装：一次准备，四个工位

准备 Python 3.9+，以及能读取技能、读写本地文件的 Codex 环境。从仓库页面选择 **Code → Download ZIP** 并解压，或使用 **Code** 菜单给出的 Git 地址克隆。进入包含本项目 `README.md` 的根目录后运行：

```bash
python scripts/install.py --dry-run
python scripts/install.py
```

第一条只检查源文件、同名冲突与目标路径，不写入文件，也不验证目录写权限。第二条复制四个完整技能，默认目标是用户级 `~/.agents/skills`。两条都不下载依赖、不安装模型、不接入生图服务、不修改 Codex 配置。

安装路径依据 [Codex 官方技能文档](https://developers.openai.com/codex/skills/)。Codex 可以发现新增技能；未显示时重启后再检查。运行 `/skills` 或输入 `$` 查看可调用技能。

### 选择自己的安装位置

```bash
# 项目级安装：把路径换成你的创作项目根目录。
python scripts/install.py --dest /path/to/your-project/.agents/skills
```

Windows PowerShell：

```powershell
python scripts/install.py --dest "$HOME/.agents/skills"
```

已有旧版安装时，先检查当前 Codex 实际加载的目录。脚本支持 `--dest` 指定该目录，但遇到任何同名技能都会在复制前退出。先备份并自行处理旧目录，再重新安装；不要同时保留多个会被加载的同名版本。

安装器会整体复制 `SKILL.md`、`agents/`、`references/` 及各技能现有的脚本或模板；不要只复制入口文件。

## 第一步：把故事说出来

```text
使用 $manga-screenwriter 开始一个新项目。
项目名：末班来信
项目目录：./projects/末班来信

故事种子：午夜，废弃车站只为失去至亲的人亮灯。
女孩要找回母亲，母亲却在广播中让她别上车。

我希望是以亲情为核心的悬疑故事，采用真人电影质感。
先做 Round 1 项目定位、核心冲突、世界观和主要人物，
将本轮成果、项目记录和状态仓保存到项目目录。
```

此时得到的是**待确认的项目方向**，不是正式全剧。编剧默认规格为 80 集、单集全文 600–800 字、正文每批连续 5 集；要修改规格，在项目定位时明确提出并写入项目记录。

## 第二步：确认方向，再进入下一阶段

编剧流程按当前规则依次推进：

```text
Round 1 项目定位与人物 → 确认
Round 2 全剧结构与关键节点 → 确认
Round 3 全剧总览 → 确认 → 每批 10 集详细大纲 → 全量确认
Round 4 每批 5 集正式正文 → 第 80 集收束
Round 5 有证据的审核与修订
```

在待确认节点，明确回复具体成果，例如：

```text
确认本轮《末班来信》的项目定位、人物关系与世界规则，继续 Round 2。
```

下次打开项目时，不必重新讲一遍故事：

```text
使用 $manga-screenwriter 接续 ./projects/末班来信。
先读取项目记录、状态仓与当前有效材料，
按实际进度完成下一合法步骤，不重建已确认内容。
```

普通“继续”在编剧确认门前不等于批准；进入详细大纲与正文后，根据文件中的进度顺延。视觉 DNA 有自己的版本确认规则，不能把不同技能的“继续”语义混为一谈。

## 第三步：确立这个世界的视觉

有可用故事材料，且明确选择真人电影质感后：

```text
使用 $ai-series-visual-dna 为 ./projects/末班来信 建立视觉 DNA。
读取该项目当前有效的项目记录、定位、人物世界设定、结构、大纲、正文与审核状态。
准确标注已提供材料的范围；沿用同一项目根目录。
采用真人电影质感，先建立 STYLE-BASE，本轮不生图。
```

确认实际发布的精确 `STYLE-BASE` 版本后，再进入美术。没有请求图片验证时，不把文本审核描述成已经完成实图验证。

## 第四步：建设资产库

```text
使用 $ai-series-art-director 读取本项目已确认的精确 STYLE-BASE 版本
与可定位场次的剧本，建立角色、群众、核心场景和重要道具资产库。
交付通过校验的 approved ASSET-INDEX 与所引用实体文件。
本轮只做资产文本和图版提示词，不生图。
```

执行前必须提供实际文件路径与确认依据；不要把 `latest` 或上面的示例描述当成精确版本。如果下一步需要白膜，另行明确请求相关资产参考图，并确保生成工具可用。

## 第五步：给一场戏安排摄影机

```text
使用 $ai-series-storyboard-master 为《末班来信》处理我指定的一场戏。
剧本文件：填写实际文件路径
场次标题或 ID：填写唯一场次
STYLE-BASE：填写已确认的精确版本路径
ASSET-INDEX：填写 approved 索引的精确版本路径

先校验上游，再交付本场计划与英文分镜，保留原文对白。
相关资产参考图和 Blender MCP 可用时，按技能流程完成独立白膜预演；
条件不足则明确报告阻塞，不声称已经渲染。
```

分镜默认处理**一场戏**。处理下一场时明确指定场次或范围；已批准分镜后的“继续”不能自动变成“把所有后续场次都做完”。

## 遇到卡点，先检查这四件事

| 现象 | 检查位置 |
| --- | --- |
| 技能没有出现 | 安装目标是否在当前环境的加载路径中；是否存在重名旧版；重启后再检查。 |
| 提示等待确认 | 项目记录中的待确认成果，以及当前技能自身的确认规则。 |
| 无法进入美术或分镜 | 精确 STYLE-BASE、确认依据、approved 资产索引、当前实体文件是否齐全且版本一致。 |
| 有分镜，没有白膜 | 对应资产参考图、Blender MCP、媒体工具是否可用；文本分镜与白膜状态分别判断。 |

各技能入口是规则来源：[编剧](../manga-screenwriter/SKILL.md)、[视觉 DNA](../ai-series-visual-dna/SKILL.md)、[美术](../ai-series-art-director/SKILL.md)、[分镜](../ai-series-storyboard-master/SKILL.md)。本指南提供调用示例，不代替技能内部的质量验收。
