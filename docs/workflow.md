# 从故事到镜头：制作指南

[返回首页](../README.md) · [安装与上手](quick-start.md) · [故事示例](../examples/last-train.md)

## 当前版本走到哪里

**oh-my-director 的目标是让一个念头走向一部完整的电影级漫剧。当前仓库实现的是四阶段创作与预演工作流，不是已经接通声音、成片生成和剪辑的自动制片系统。**

```text
已提供的创作链
故事种子 → 编剧 → 视觉 DNA → 美术资产 → 单场分镜 → 白膜预演
                                                        ↓
另行接入的制作链
正式视频生成 → 配音与声音设计 → 配乐 → 剪辑与成片验收
```

白膜是调度检查用的极简预演，不是最终画质样片。完整的文本流程也不等于已经完成生图、渲染或整剧成片。

## 各阶段的交付与依赖

| 阶段 | 正式交付 | 环境与前置条件 |
| --- | --- | --- |
| 编剧 | 定位、结构、大纲、正文、状态仓、项目记录与审核材料 | 能力合适的语言模型，以及可读写项目文件的运行环境。 |
| 视觉 DNA | 版本化 `STYLE-BASE` | 有效故事材料；进入下游前确认精确风格版本。请求实图验证时才需要图像工具。 |
| 美术 | `approved` 资产索引、实体基础设定与图版提示词 | 已确认的真人电影 STYLE-BASE、可定位场次的材料。参考图按明确请求另行生成。 |
| 分镜 | 单场计划、片段英文主稿、原文对白与资产绑定 | 当前剧本、精确 STYLE-BASE、approved 索引、本场所需实体文件。 |
| 白膜 | 每片段独立视频、工程及执行描述 | 已通过校验的分镜、相关资产参考图、真实 Blender MCP 执行，以及渲染、编码和媒体检查条件。 |

各技能已有的 Python 校验器用于检查结构与引用等确定性要求；通过脚本不能替代剧作、视觉、表演与连续性的语义审核。

## 交接不靠一句“差不多了”

### 编剧 → 视觉 DNA

沿用同一个项目根目录。交接项目记录、已确认定位与人物世界设定、全剧结构、大纲、现有正文和审核状态，保留**路径、版本、范围、确认依据与待决项**。材料可以不是完整全剧，但必须如实标注覆盖范围。剧本确认不代替视觉风格确认。

### 视觉 DNA → 美术

只交接用户已经确认的精确 `STYLE-BASE` 版本。视觉 DNA 定义全剧不变量；美术将其转译为可见的实体设计，不另造一套全局风格。

### 美术 → 分镜

提供精确 `approved ASSET-INDEX`，以及本场引用的当前角色、群众、场景和重要道具文件。共同引用同一 STYLE-BASE；不能从聊天记忆重建已批准资产，也不能用临时描述绕过缺失的重要资产。

### 分镜 → 白膜

锁定正式分镜的视觉内容与来源指纹，读取所有相关资产参考图，再通过 Blender MCP 完成制作。白膜无声、无字幕，以轮廓、空间、动作与道具状态为重点；每片段独立交付，不默认拼成全场合辑。

## 确认只发生在需要决策的地方

| 阶段 | 确认方式 |
| --- | --- |
| 编剧 | 项目定位、全剧结构、完整总览及全量详细大纲有确认门；不额外要求每批正文重复审批。 |
| 视觉 DNA | 精确版本发布后确认一次。指向唯一、无冲突的直接回复按该技能规则消费确认，不反复索要同一版本的批准。 |
| 美术 | 首次合格交付直接为 `approved`；用户明确要求实质修改时创建新版本。 |
| 分镜 | 首次通过校验直接为 `approved`；新白膜依赖另行检查，不通过增加文本审批来解决缺图。 |

“少打断”不等于“无门槛”。普通美术设计空间可以主动补全；涉及身份、能力、关键因果、必须满足的空间关系或已确认风格冲突时，仍要解决关键未知。

## 三条不会因品牌升级而变化的边界

**叙事形态与视觉本体分开。** 编剧处理中文漫剧叙事；本仓库的视觉 DNA 与美术针对真人电影质感，可包含符合题材的电影视效。需要动画视觉时，采用兼容的完整动画链路，不能把动画风格强塞进本仓库的真人美术流程。

**编剧规格与视频规格分开。** 编剧按故事推进与字数要求创作，不用固定秒数倒推整集正文。分镜阶段另有大于 0 且不超过 30 秒、每片段 6–12 镜的内部规则。这个上限不是 Seedance 或任何实际生成入口的单次提交承诺；正式提交前核对所用平台版本与配置。

**文本成果与媒体成果分开。** 提示词完成不等于图片生成，分镜通过不等于白膜渲染，白膜交付不等于正式成片。缺失依赖时记录准确阻塞范围，不能把未执行项目登记为通过。

## 修改之后，怎样继续

保持当前有效文件路径与版本索引清晰，修订时保留旧版，定位受影响的故事事实、风格规则、资产或场次。未修复冲突不得作为有效材料继续使用；未引用资产的升级也不应无条件让所有场次失效。

继续创作时先读文件，先核对当前进度、范围与版本，再执行下一合法步骤。完整项目是否完成，应由真实材料与验收覆盖决定，而不是由聊天中出现“完成”两个字决定。
